# M3: ブロック編集と自動保存

完了日: 2026-11-06 / ブランチ: `codex/block-editor-autosave`

BlockNote 0.57を導入し、文章・見出し・各リスト・チェック・引用・コード・表・画像・ファイル・区切り・リンク、KaTeX数式、時刻付き操作手順を利用可能にした。標準のスラッシュメニュー、ドラッグ、インデント、undo/redoに加え、上へ・下へ・複製操作を用意した。画像・ファイルのローカルアップロードは予定どおりM5で接続する。

編集後700ms以上待って保存する。送信を直列化し、送信中の追加編集は次の送信に回す。未送信本文と基準更新番号をlocalStorageへ保持し、再読み込み・通信復帰時に再送する。保存APIの409では再送を止め、下書きJSONのダウンロードと、確認付きの最新内容再取得を案内する。ブラウザ保存領域の不足も表示する。基本情報と本文は同じ更新番号を利用し、競合時は上書きしない。

検証: 本番ビルド・型チェック・単体22件・Chromium E2E 7件が成功。全ブロック種別の追加・複製・移動・再表示、文字入力とundo/redo、503時の下書き復元と再送、旧更新番号の409を確認した。従来のM2操作も回帰検証した。

残課題: M4の参照、M5の測定・アップロード、M6のリンク収集、M7の復旧手順は後続ブランチで実施。ブラウザ内下書きは同じブラウザ・同じオリジンでのみ復元できる。大きなデザイン変更は行っていない。

参照: [BlockNote導入](https://www.blocknotejs.org/docs/getting-started)、[カスタムブロック](https://www.blocknotejs.org/docs/features/custom-schemas/custom-blocks)。Next.jsは同梱ガイドのclient component・route handlerを参照。
