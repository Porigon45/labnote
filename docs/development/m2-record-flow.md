# M2: アプリシェルと基本記録フロー

完了日: 2026-11-05

## 実装範囲

- 左サイドバー・ヘッダー・中央領域・右情報パネルのPCレイアウト。
- `/`: 件数、最近の日次記録（更新順・最大8件）、進行中の実験シリーズ。
- `/projects`: プロジェクト一覧と作成フォーム。
- `/projects/[id]`: 所属する実験シリーズの一覧と作成フォーム。
- `/series`: 実験シリーズの横断一覧と所属プロジェクト名。
- `/series/[id]`: 日次記録の日付降順一覧と作成フォーム。
- `/entries/[id]`: 日次記録のタイトル・日付・状態の編集と明示保存。
- プロジェクト → 実験シリーズ → 日次記録のパンくずとリンク。
- 状態は予定・進行中・完了。作成時の既定値は進行中、日次記録の日付は日本時間の当日。

## 保存・表示

Next.js同梱ガイドのServer Actions・非同期paramsに従い、既存のM1保存層を呼び出す。SQLite接続は操作ごとに閉じる。読み取りページはリクエスト時にDBから取得し、保存後に画面を再検証する。スキーマ変更や追加マイグレーションは不要。

保存処理は種類、タイトル、状態、必須日付、親の種類と可視性をサーバーでも検証する。日付の妥当性は保存層で検証する。日次記録の編集では更新番号を渡し、競合時は上書きせずエラーを表示する。エラー時も入力値を保持し、保存中は送信ボタンを無効化する。

親から継承するアーカイブ状態も考慮して、一覧・最近の記録・詳細URL・作成先から除外する。存在しないIDや種類の異なるURLは記録が見つからない画面を表示する。

本文ブロック編集・自動保存はM3、プロトコル等のナビゲーションと関連情報はM4以降、アーカイブ操作はM6で実装する。
