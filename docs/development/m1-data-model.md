# M1: データモデルと永続化

実装日: 2026-11-05

## 保存構成

`records` を共通の記録基盤とする。種類は研究テーマ、プロジェクト、実験シリーズ、日次記録、プロトコル、試料、研究メモ、自由ページ。タイトル、ブロック本文JSON、目的・仮説、状態、日付、カテゴリ、更新番号、アーカイブ日時を保存する。

プロジェクトは任意の研究テーマに所属し、実験シリーズはプロジェクト、日次記録は実験シリーズに必ず所属する。M1では所属変更を提供しない。タイトルは必須、日次記録には日付を指定する。

追加テーブル:

- `samples`: 試料種別、由来、親試料、保管場所。外部キーとトリガーで不正な参照・親子の循環を拒否する。
- `protocol_versions`: 編集時点のタイトル・本文を追記保存する。過去版の更新・削除をDBで拒否する。
- `protocol_snapshots`: 日次記録と使用時点のプロトコル版、変更点を関連付ける。版は不変なので参照だけで使用時の内容を保持できる。
- `measurements`: 軸名・単位、試料系列、測定値JSON。欠測値はnullで保持する。
- `attachments`: 元ファイル名、保存キー、MIME、サイズ、キャプション。ファイル本体のアップロードはM5。
- `content_links`、`tags`、`record_tags`: 記録間の関連とタグ。二重登録を防ぐ一意制約を持つ。

## 保存層

`createRepository(connection)` が作成、更新、一覧、詳細、アーカイブ・復元、タグ、関連付け、試料、プロトコル使用、測定・添付メタデータの保存を提供する。公開HTTP APIと編集画面はM2以降で実装する。

更新時は期待する更新番号を渡す。現在の番号と一致しなければ `ConflictError` で拒否し、既存内容は保持する。複数テーブルへの保存はトランザクションで行い、一部失敗時は全体を戻す。

親がアーカイブされると子も通常一覧から隠す。子自身のアーカイブ状態は変更しないため、親の復元で元の一覧へ戻る。詳細取得はアーカイブ済み記録にも対応する。完全削除の保存層APIは設けない。

SQLマイグレーションに外部キー、CHECK、一意制約、トリガーを定義する。`schema.ts` はDrizzleの型付きアクセス用定義。変更時は両方を更新し、既存マイグレーションを書き換えず新しいSQLを追加する。

## 検証

一時SQLite上でマイグレーション再実行、試験データ作成、DB再接続後の再取得、階層制約、更新競合、過去プロトコルの不変性、試料循環の拒否とロールバック、アーカイブ復元、タグ・リンク重複防止、測定値と添付情報の保存を検証する。

`seedResearchFixture` はテスト用データの生成関数。起動時や実DBのマイグレーション時には呼び出さない。

検証結果: 型チェック、本番ビルド、単体・統合テスト22件、Chromium E2E 2件が通過。既存のM0データベースへのマイグレーションと再実行も成功した。
